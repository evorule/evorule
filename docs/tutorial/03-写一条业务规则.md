# 教程 03 · 写一条业务规则(用 evorule CLI)

> **目标**:用 JSON 写业务规则、用 `evorule` CLI 跑、看 fact log、校验规则、验证审计链。
> **受众**:规则作者 / 业务分析师 / 任何不想写 Rust 的人。
> **前置**:`cargo install evorule-cli`(或从源码 `cargo install --path evorule-cli`)。

## 1. 准备规则目录

```bash
mkdir my-first-rule
cd my-first-rule
```

新建 `rules/` 子目录(CLI 期望一个目录,里面放一个或多个 `*.json` 规则文件):

```bash
mkdir rules
```

## 2. 写第一条业务规则

把以下内容保存为 `rules/01-greet.json`:

```json
{
  "rule_id": "demo.greet",
  "version": "0.1.0",
  "metadata": {
    "author": "you",
    "description": "noop 触发时把 greeting 设为 hello"
  },
  "transform": [
    {
      "type": "branch",
      "params": {
        "domain": {
          "type": "instruction",
          "instruction_type": "noop"
        },
        "on_true": [
          {
            "type": "set",
            "params": {
              "attr": "greeting",
              "operation": "set",
              "value": "hello, evorule"
            }
          }
        ]
      }
    }
  ]
}
```

**规则解释**:

- `transform[0]` 是一条 `branch` 元指令,匹配 `instruction_type == "noop"`
- `noop` 是 CLI 启动时自动构造的初始指令(见 [CLI_SPEC.md](https://gitee.com/evorule/evorule/blob/main/evorule-cli/CLI_SPEC.md))
- 当 `noop` 触发时,执行 `on_true`:把 payload 的 `greeting` 字段设为 `"hello, evorule"`

> **更复杂的指令触发**(如 `increment`、`decrement`、自定义业务指令)需要通过
> `evorule-server` 的 HTTP API（见 evorule-server 独立仓）。

## 3. 跑

```bash
evorule run rules/
```

你应该看到类似输出(fact log,JSON Lines 格式,每行一条 Fact):

```jsonl
{"kind":"Command","id":0,"instruction":{"type":"noop"}}
{"kind":"PayloadUpdate","cause":0,"path":"greeting","new_value":"hello, evorule"}
{"kind":"StateTransition","cause":0,"from":0,"to":1}
{"kind":"Stable","cause":0,"final_snapshot":{"greeting":"hello, evorule"},"steps":1}
```

**这 4 条 Fact 完整描述了一次执行**:

1. `Command`:CLI 提交了 `noop` 指令(FactId 0)
2. `PayloadUpdate`:引擎把 `greeting` 字段写为 `"hello, evorule"`
3. `StateTransition`:反应器从状态 0 推进到状态 1
4. `Stable`:反应器收敛(队列空 + 无待处理 I/O),终止

## 4. 保存到文件

```bash
evorule run rules/ -o facts.jsonl
ls -lh facts.jsonl
```

> `-o` / `--output` 指定输出文件,默认 stdout。文件格式仍是 JSONL,
> 与 [evorule-reactor WAL](https://docs.rs/evorule-reactor) 互通。

## 5. 校验规则

```bash
evorule validate rules/
```

合法规则输出:

```
[OK]   transform[0]: type='branch'
✅ 通过 schema gate (0 errors)
```

**不合法规则**举例(把 `branch` 改成 `noop`——`noop` 是业务指令不是元指令):

```json
{ "transform": [{ "type": "noop" }] }
```

```
❌ transform[0] 的 type 'noop' 不在白名单中
   (合法值: branch, set, push, io_request, collect, merge)
```

> 元指令集 6 种(`branch` / `set` / `push` / `io_request` / `collect` / `merge`)
> 与 TCB 引擎 dispatch 严格对齐——参见元指令集参考（待发布）
> 和双层语言原理（待发布）。

## 6. 重放

```bash
evorule replay facts.jsonl
```

把 JSONL 格式的 fact log 重新 pretty-print 成人类可读格式:

```
Command      #0  noop
PayloadUpdate    greeting = "hello, evorule"  (cause: #0)
StateTransition  #0 → #1
Stable       final: {"greeting": "hello, evorule"}  (1 steps)
```

## 7. 验证审计链

```bash
evorule verify-chain facts.jsonl
```

合法链输出:

```
✅ 哈希链完整(0 errors)
```

被篡改的链会立即报错:

```
❌ line 3: content hash mismatch
   expected: ...
   actual:   ...
```

> `evorule verify-chain` 使用 BLAKE3 哈希链,任何对历史 fact 的修改都会被检测出。
> 完整原理见审计链说明（待发布）。

## 8. 对比两次执行(diff)

跑两次 `evorule run rules/`,保存到不同文件:

```bash
evorule run rules/ -o run1.jsonl
# 修改规则,把 value 改成 "goodbye, evorule"
evorule run rules/ -o run2.jsonl

evorule diff run1.jsonl run2.jsonl
```

输出两条执行的 fact 差异(按 FactId 下标对齐):

```
Command      #0  noop  (相同)
PayloadUpdate  greeting = "hello, evorule"   →  "goodbye, evorule"  (cause: #0)  [DIFF]
StateTransition  #0 → #1  (相同)
Stable       final: ...  (相同结构,不同 value)
```

## 关键概念

| 概念 | 含义 |
|---|---|
| `core_eval` | 一组 transform 规则,顺序执行 |
| `noop` | 初始指令,CLI 启动时自动构造 |
| `branch` 元指令 | 条件分支,匹配 `domain` 后执行 `on_true` |
| `set` 元指令 | 改 payload 字段,支持 `set`/`add`/`sub` 三种 operation |
| `Fact` | 反应器对世界的一次陈述(8 种) |
| **审计链** | BLAKE3 哈希链,任何篡改可检测 |

## 子命令速查

| 子命令 | 用途 | 关键参数 |
|---|---|---|
| `evorule run` | 跑规则,输出 fact log | `<rules_dir> [--payload JSON] [--payload-file PATH] [-o FILE] [--max-steps N]` |
| `evorule replay` | pretty-print fact log | `<fact_log>` |
| `evorule diff` | 对比两个 fact log | `<a> <b>` |
| `evorule validate` | 校验 JSON 规则文件 | `<rules_dir>` |
| `evorule verify-chain` | 验证 fact log 哈希链 | `<fact_log>` |

## v0.3.2 格式说明

- **core_eval.json 新增元数据字段**: `$schema`（JSON Schema 引用）、`kind`（固定值 `"rule_set"`）、`id`（规则集唯一标识）。本教程示例为简化格式，完整格式请参考 `evorule-tcb/core_eval.json`
- **元指令白名单**: 仅 6 种真元指令（branch/set/push/io_request/collect/merge）。`noop`/`increment`/`decrement` 是**业务指令层**类型（如本教程中的 `noop` 初始指令），不是元指令，不得混入元指令白名单
- **路径边界收紧**: 以点号结尾的路径（如 `"x."`）现在返回 `None`（非法语法），之前会被静默接受
