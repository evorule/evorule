## 1. 核心立场

**不白送。**

大厂 fork 之后想"卖闭源 SaaS"也得开源他们的服务。内部用 AGPL 管不到（也没必要），但 fork 这个行为本身 = 我们的胜利。

| 场景                     | 我们的态度         | 协议工具     |
| ------------------------ | ------------------ | ------------ |
| 个人学习、研究、内部使用 | 免费，随便用       | AGPL 不限制  |
| 开源项目集成             | 免费，但你也得开源 | AGPL 传染性  |
| 公益/学术机构            | 免费，可闭源       | 免费商业豁免 |
| 商业公司闭源 SaaS        | 付费，买商业许可   | 商业许可     |

## 2. 为什么选 AGPL-3.0

### 2.1 与其他许可证的对比

| 许可证           | SaaS 需要开源吗？                     | 传染性 | 适合我们吗？ | 原因                                          |
| ---------------- | ------------------------------------- | ------ | ------------ | --------------------------------------------- |
| MIT / Apache-2.0 | ❌ 不需要                             | 无     | ❌           | 大厂直接 fork 改个名字卖闭源 SaaS，白送       |
| GPL-3.0          | ❌ 不需要（仅分发触发）               | 强     | ❌           | 有 SaaS loophole，网络服务不算"分发"          |
| LGPL-3.0         | ❌ 不需要                             | 弱     | ❌           | 既有 SaaS loophole，传染性又弱                |
| BSL / SSPL       | ✅ 需要（但不是 OSI 认证）            | 自定义 | ❌           | SSPL 不是开源协议，BSL 最终转开源但时间不可控 |
| **AGPL-3.0**     | ✅ 需要（网络用户也有获取源码的权利） | 强     | ✅           | OSI 认证的开源协议，封死 SaaS loophole        |

### 2.2 AGPL-3.0 的关键条款

1. **网络服务也算分发**：如果你通过网络向用户提供基于 EvoRule 的服务，用户有权获取你的完整源代码（包括你修改的部分）。
2. **传染性**：如果你修改了 EvoRule 或基于 EvoRule 构建衍生作品，整个作品必须以 AGPL-3.0 或兼容许可证发布。
3. **保留版权声明**：不得移除原始版权和许可证声明。
4. **不提供担保**：按"原样"提供，作者不承担任何责任。

### 2.3 为什么不"更开放一点"？

因为我们的目标不是"最多的使用者"，而是"最健康的生态"。

- 如果用 MIT/Apache，大厂会 fork 然后闭源赚钱，社区得不到任何回馈
- 如果用 GPL-3.0，SaaS loophole 会被大厂利用（"我们只是在内部运行，不分发"）
- AGPL-3.0 是**开源协议中最强的保护**，确保任何人通过网络提供服务都必须回馈社区

**我们不怕用的人少，我们怕被白嫖。**

## 3. 生态协议矩阵

EvoRule 不是一个项目，是一个生态。不同层级的协议策略不同：

| 层级        | 项目                        | 许可证                | 理由                                         |
| ----------- | --------------------------- | --------------------- | -------------------------------------------- |
| **核心**    | evorule (tier0/tier1/tier2) | **AGPL-3.0-or-later** | 核心引擎，必须保护不被白嫖                   |
| **AI 编排** | evo-agent                   | **AGPL-3.0-or-later** | 应用层，与核心紧密绑定                       |
| **SDK**     | TypeScript SDK              | **MIT**（待确认）     | 鼓励集成，越多人用越好，SDK 本身不是核心价值 |
| **SDK**     | Python SDK（规划中）        | **MIT**（待确认）     | 同上                                         |
| **宪法**    | `core_eval.json`            | **CC0-1.0**           | "宪法属于全人类"，规则本身不应受版权限制     |
| **文档**    | 所有文档                    | **CC0-1.0**（建议）   | 知识自由传播                                 |

### 3.1 为什么 SDK 用 MIT？

SDK 是"胶水层"，价值在于降低集成门槛。如果 SDK 也是 AGPL，企业会因为协议顾虑而不敢集成，反而限制了生态扩张。核心引擎才是价值所在，SDK 越普及越好。

### 3.2 为什么 core_eval.json 是 CC0？

`core_eval.json` 是 EvoRule 的"宪法"——定义了系统支持的所有 transform 指令。它更像一个标准/规范，而不是创造性作品。如果宪法受版权保护，那任何人实现兼容的规则引擎都有法律风险，这与"让规则驱动普及"的目标相悖。

## 4. 双轨许可策略

详见 [DUAL_LICENSE.md](../DUAL_LICENSE.md) 和 [FREE_COMMERCIAL_LICENSE.md](../FREE_COMMERCIAL_LICENSE.md)。

这里只讲战略逻辑：

```text
                    ┌─────────────────────┐
                    │    AGPL-3.0 开源     │
                    │   （免费，但要开源）  │
                    └──────────┬──────────┘
                               │
               ┌───────────────┼───────────────┐
               ▼               ▼               ▼
        个人/内部用       开源项目         公益/学术
       （不受影响）    （AGPL 兼容）    （免费商业豁免）

                    ┌─────────────────────┐
                    │     商业许可         │
                    │   （付费，可闭源）    │
                    └──────────┬──────────┘
                               │
               ┌───────────────┴───────────────┐
               ▼                               ▼
        企业闭源 SaaS                   商业产品集成
    （不想开源自己的服务）          （不想开源自己的产品）
```

**为什么有免费商业豁免？**

公益、学术、公共服务机构用我们的软件是在做好事，不应该让他们付钱。但他们可能有合规要求（不能用 AGPL），所以提供免费的商业许可豁免。

## 5. 常见问题

### Q: 我在公司内部使用 EvoRule，需要开源吗？

**不需要。** AGPL-3.0 只在你**通过网络向第三方提供服务**或**分发给第三方**时触发开源义务。公司内部使用（不对外提供服务）完全不受限制。

### Q: 我 fork 了 evorule，改了个名字，用来提供 SaaS 服务，可以吗？

**可以，但你必须开源你修改后的全部源代码**（包括你新增的功能），并且你的服务也必须以 AGPL-3.0 许可。如果不想开源，请购买商业许可。

### Q: 我用了 EvoRule 的 TypeScript SDK，我的应用需要开源吗？

**不需要。** SDK 计划使用 MIT 许可（待确认），不具有传染性。但 SDK 调用的 EvoRule 服务器本身仍然是 AGPL-3.0。

### Q: 我可以基于 EvoRule 做商业产品吗？

**可以，两种选择：**

1. 你的产品也开源（AGPL-3.0 兼容）—— 免费
2. 你的产品闭源 —— 购买商业许可

### Q: 为什么不搞"开源核心 + 企业版功能"？

因为那会导致开源版是"残血版"，社区体验差。我们的模式是：**代码全开源，协议收钱**。代码本身没有任何阉割，你拿到的就是完整版。区别只在于你能不能闭源商用。

### Q: 如果有人违反 AGPL 怎么办？

1. 先友好联系，要求合规（开源或停止使用）
2. 拒不配合的，公开曝光 + 法律行动
3. 我们有商标保护，可以禁止使用 EvoRule 品牌

### Q: 未来会换许可证吗？

不会轻易换。如果要换，需要：

- 所有版权持有者同意（当前：Mr. DAMU ZHENG）
- 不影响已发布版本的许可证
- 提前 6 个月公告
