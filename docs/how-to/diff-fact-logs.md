# How to Compare Two Fact Chains

> Task: compare the fact logs of two executions and find the differences (aligned by FactId order, not a naive set comparison).

## Steps

```bash
evorule diff run-a.jsonl run-b.jsonl
```

Code basis: `evorule-cli/src/commands/diff.rs` L26-45.

## Comparison logic

`diff` aligns the two logs by **array index** (FactId order) and compares fact by fact (diff.rs L50-88):

| Marker | Meaning |
|------|------|
| `[~]` | Present on both sides but with different content |
| `[-]` | Present only in A |
| `[+]` | Present only in B |
| `(identical)` | Completely identical |

> Design decision (diff.rs L14-16): LCS (longest common subsequence) is deliberately not used, because Facts have no naturally ordered notion of "lines" — LCS would misalign matches and lose id-mismatch information. Aligning by FactId is the correct approach for causal-chain semantics.

## Output example

```
=== Diff run-a.jsonl <-> run-b.jsonl ===
A: 5 facts
B: 4 facts

[-] F2 [StateTransition] cause=F1 payload_keys=[counter] queue_len=0
[~] F3 [Stable] version=2
[~] F3 [Stable] version=1

=== 2 difference(s) ===
```

## Use cases

1. **Regression testing**: after modifying rules, compare the old and new execution results
2. **Debugging**: execution differences of the same rule with different payloads
3. **Audit**: compare "what should have happened" with "what actually happened"

## FAQ

**Q: Can two logs of different lengths be compared?**
A: Yes. diff lists the `[-]` (only in A) and `[+]` (only in B) parts separately.

**Q: How are Fact IDs generated?**
A: A Fact ID is an incrementing number of the execution order (starting from 0), generated by `FactIdGenerator` (reactor fact.rs L129). Unique within a single execution.

**Q: Can diff detect hash chain tampering?**
A: No. diff only compares Fact content and does not verify the hash chain. To verify integrity use `evorule verify-chain`.
