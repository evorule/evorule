# evid-verify-wasm

Wasm bindings for the EvoRule EVID verifier: bring audit-chain verdicts into the browser/JS side — **install-free, zero network requests, verdict semantics byte-for-byte same-sourced with the Rust kernel**. All verdict logic is delegated to [`evid-verify-core`](https://github.com/evorule/evorule/tree/main/evid-verify-core); this crate only handles JSON message shapes (handlers share the verdict layer, never panic, and parse failures likewise produce a structured red).

## Two routes

### route A — extern "C" byte ABI (default build, the install-free primary artifact)

Zero imports, zero JS glue — usable as soon as `WebAssembly.instantiate` yields the module (mounts no host imports). Three entries: `verify_export_wasm` / `verify_wal_wasm` / `verify_seals_wasm`.

Calling contract (four steps on the JS side):

```js
const p = wasm_alloc(n);            // 1. Allocate the input buffer
//    write the n-byte JSON (input = {"entries":[...]} etc., the matching surface's message)
const out = verify_export_wasm(p, n); // 2. Verdict (wal/seals entries share the same shape)
wasm_free(p, n);                    // 3. Return the input buffer
const len = getUint32(out, true);   // 4. Output = [u32 LE length][JSON bytes] packet
//    after reading, call wasm_free(out, 4 + len) to return it
```

No path panics (workspace lints deny the panic family); null pointers / zero-length inputs return a structured error packet.

### route B — wasm-bindgen binding surface (`--features bindgen`)

wasm-pack / npm ecosystem friendly, strings in and out (e.g. `verify_export_json(input) -> String`). Not in the default build — wasm-bindgen mounts host imports into the module, breaking route A's zero-import install-free instantiation.

```bash
wasm-pack build --target web --out-dir dist/bindgen -- --features bindgen
```

## Single-file HTML verifier (the install-free deliverable)

`dist/index.html` (generated by `build-dist.ps1`) — a **single-file** verifier with the wasm base64 embedded:

- File drag-and-drop / paste, dual import channels;
- Public keys pasted manually per `key_id` to build the table, **zero hard-coded trust roots** (you decide whom to verify);
- Export / WAL / anchor three-surface verdict UI, showing verdicts and rejection reasons per entry;
- **Zero network requests** — air-gapped / confidential environments can distribute it directly offline.

The six-piece fixture set under `dist/fixtures/` shipped with the repo are frozen browser-tested vectors (the CI `evid-wasm-gate` proves it on every run: the wasm32 artifact is compared byte-for-byte against host verdict results on the seven frozen vectors).

## Build

```bash
# route A (cdylib, zero imports)
cargo build -p evid-verify-wasm --target wasm32-unknown-unknown --release

# Single-file HTML verifier
pwsh ./build-dist.ps1
```
